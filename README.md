# Toxic Comment Classification — From Kaggle Notebooks to a Served Model

Multi-class (4-level) toxicity classification on ~198k comments with severe class imbalance.
Built under a classical-ML constraint (no neural nets, no NLTK/spaCy), evaluated with Macro-F1,
then extended with leak-free validation, ablations, error analysis, a bias audit, a transformer
comparison and a containerised API.

| | |
|---|---|
| **Kaggle result** | Public-leaderboard Macro-F1 **0.826** (approx. rank 140-155 of 600+ teams) |
| **Final model** | 4-model stacking ensemble (calibrated LinearSVC, LogReg, SGD, calibrated Passive-Aggressive) -> LogReg meta-learner, on 60,019 sparse features |
| **Stack** | Python, scikit-learn, SciPy, FastAPI, Docker, pytest, GitHub Actions |
| **Training** | Kaggle notebooks (the original experiments, kept as evidence) + Google Colab (leak-free re-evaluation and export) |

> Reproduced, leak-free numbers live in [`results/metrics/SUMMARY.md`](results/metrics/SUMMARY.md) (generated by
> [`notebooks/colab_final_evaluation.ipynb`](notebooks/colab_final_evaluation.ipynb)). Where this README quotes a
> score, it says whether it is the Kaggle leaderboard, a single notebook split, or cross-validation.

## 1. The problem

| Label | Meaning | Train share |
|:--:|---|--:|
| 0 | Neutral | 57.7% |
| 1 | Mildly problematic | 8.0% |
| 2 | Moderately toxic | 31.5% |
| 3 | Severely toxic | 2.7% (hardest; 21:1 vs class 0) |

197,999 training rows, 102,000 test rows; text plus metadata (votes, emoticons, timestamps, identity-mention flags).
**Metric: Macro-F1**, which weights the rare severe class as much as the majority class, so accuracy and
majority-class tricks do not help.

## 2. Approach in one picture

```
raw record ──► clean_text (lowercase, strip URLs/HTML/emails/numbers; no stemming)
          ├─► word TF-IDF 1-3 grams, 35k    ┐
          ├─► char_wb TF-IDF 3-5 grams, 25k ├─► sparse hstack (60,019 dims) ─► 4 base models ─► 16 probabilities ─► LogReg meta ─► label
          └─► 14 numeric (log1p + StandardScaler) + 5 binary ┘     (all class_weight='balanced')
```

Base models: `CalibratedClassifierCV(LinearSVC C=0.1)`, `LogisticRegression C=1`, `SGDClassifier(log_loss)`,
`CalibratedClassifierCV(PassiveAggressive C=0.1)`; stacking uses 3-fold out-of-fold predictions.
Code: [`src/milestone_5_final.py`](src/milestone_5_final.py) (the submitted notebook as a script) and the serving
version [`src/toxic_pipeline.py`](src/toxic_pipeline.py).

## 3. How the score evolved (Kaggle leaderboard)

| Milestone | Change | Macro-F1 |
|---|---|--:|
| M1 | LogReg, 15k word TF-IDF | 0.777 |
| M2 | SGD / Ridge / PA, scaler study | 0.776 (val 0.809) |
| M3 | **LinearSVC + char n-grams** (largest jump) | 0.816 |
| M4 | Stacking ensemble | 0.823 |
| M5 | 60k features, no stop-word removal, 7 iterations | 0.826 |

Gains after M3 are small (+0.010 over four iterations). Differences of ~0.001 between M5 versions are
smaller than split-to-split noise, which is why the leak-free CV in section 5 exists.

## 4. What I tried and what I learned

| Experiment | Outcome | Honest reading |
|---|---|---|
| LinearSVC over LogReg | +0.01-0.02, 3-5x faster | Coordinate descent suits sparse high-dim data |
| Char n-grams | consistent gain | See the cleaning caveat below |
| Dropping stop words | slightly worse | "you", "not" carry toxicity signal |
| Lemmatization / stemming | identical score (NLTK) / worse (regex stemmer) | NLTK also violated the rules |
| `class_weight` vs SMOTE / oversampling | `class_weight` better | Oversampling + weights double-corrects |
| TruncatedSVD, tree models on SVD | much worse | 200-500 components keep a small share of variance |
| LightGBM meta-learner, ComplementNB base | worse | 16 inputs overfit; weak base models add noise |
| Chi² selection | much worse | **Flawed experiment**: `abs()` on scaled features. Not evidence against Chi² |
| Pseudo-labeling | OOM | Also added mostly majority-class labels |
| Threshold tuning, seed averaging | no gain | Single splits; within noise |

**Known weaknesses in the original notebooks (and how this repo addresses them)**

1. **Validation leak.** TF-IDF and the scaler were fit on all of `train` before the 80/20 split. The effect on
   the score is probably small (unsupervised statistics) but it is a methodological flaw.
   -> [`src/evaluate.py`](src/evaluate.py) fits features inside each fold.
2. **Single-split decisions.** Model choices rested on one split, no confidence intervals.
   -> 5-fold CV mean +/- std and bootstrap 95% CIs.
3. **Cleaning vs char n-grams.** `clean_text` replaces `*` with a space, so masked profanity ("f**k") is split before
   `char_wb` sees it. -> The ablation includes a variant that keeps `*!?`.
4. **No error analysis, no fairness check.** -> Added (below).

## 6. Error analysis and bias audit

`python src/evaluate.py --step holdout` writes:
* 40 sampled severe-class comments the stack misses, with predicted probabilities, for a manual error taxonomy
  (sarcasm, negation, implicit toxicity, very short text, ...) in `results/metrics/error_analysis_label3.csv`;
* the **false-positive rate on truly neutral comments per identity group** (`race`, `religion`, `gender`,
  `disability`) in `fairness_audit.csv`. A model that flags neutral comments that merely mention a group more often
  is a real-world harm even when Macro-F1 looks fine. Caveat: the identity columns are provided flags, not verified
  ground truth, and `has_detection` is itself a model input.

## 7. Serving

```bash
python src/evaluate.py --step export --data-dir data --model-dir src/model_artifacts   # or run the Colab notebook
pip install -r requirements-serve.txt
uvicorn app:app --app-dir src --port 8000
curl -X POST localhost:8000/predict -H "Content-Type: application/json" -d '{"comment": "you are an idiot"}'
```

Open `http://localhost:8000/` for a small web demo, `/docs` for the interactive API docs.

| Endpoint | Purpose | Protected |
|---|---|---|
| `GET /` | web demo page (strict CSP, no external assets) | no |
| `GET /health` | liveness | no |
| `POST /predict`, `POST /predict/batch` (<= 500) | predictions; only `comment` is required | API key + rate limit |
| `GET /info` | artifact provenance (library versions, sha256, hold-out metrics) | API key |
| `GET /metrics` | Prometheus metrics (requests, latency histogram, predicted-class mix, 401/429 counts) | API key |

Operational settings (environment): `API_KEYS` (comma-separated; unset = open demo mode), `RATE_LIMIT_PER_MIN`
(default 60 per caller, `0` disables), `TRUST_PROXY=1` (use `X-Forwarded-For` behind your own proxy), `LOG_LEVEL`, `MODEL_PATH`.
Every request gets an `X-Request-ID` and one JSON log line (method, route, status, latency, predicted labels);
**comment text is never logged** (covered by a test). The rate limiter is in-memory per process, so behind multiple
workers/instances use the gateway's limiter or a shared store such as Redis.
A single `Pipeline(FeatureBuilder -> classifier)` is saved, so train and serve cannot drift apart.
Docker: `docker build --build-arg PYTHON_VERSION=<training python> -t toxic-api .`.
Deployment options (Hugging Face Spaces, Azure Container Apps), artifact storage and monitoring:
[`docs/deployment.md`](docs/deployment.md). Scaling past RAM: [`docs/scalability_hashing.md`](docs/scalability_hashing.md).

## 8. Engineering

* 23 `pytest` tests covering the feature pipeline, API, auth, rate limiting, metrics and log privacy (`tests/`), run by GitHub Actions on every push.
* Pinned requirements; the artifact's metadata records exact library versions (pickles are version-bound).
* Reproducible split (`random_state=42`) shared by the sklearn and DistilBERT evaluations.

## 9. Limitations

* Bag-of-words cannot model sarcasm, negation scope or context; this is where the transformer comparison matters.
* The stack's gain over the best single LinearSVC is small relative to its ~8x inference cost (see section 5).
* Public-leaderboard score only; no private-leaderboard figure is claimed.
* The label definition is the competition's; the dataset's annotation process and its biases are not documented here.
* The identity-group audit uses provided flags and small subgroups; treat gaps as signals to investigate, not proof.
